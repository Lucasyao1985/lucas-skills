# LinkedIn 职位搜索 + 投递列表 — 使用说明

基于 Playwright + Google Chrome 的领英职位自动搜索工具。**国内(上海) + 海外(Remote/Worldwide) 双线并行**，锁定 AI Builder / AI Native / AI Coding Agent 类型岗位。完整流水线：搜索 → 过期检测 → 生成可筛选 HTML 投递页面。

## 0. 自然语言触发

在对话中说以下任意一句即可自动运行完整流水线：

| 最简单 | `生成投递列表` |
| 完整 | `帮我在领英上找匹配的 AI Agent 岗位，生成投递页面` |
| 其他触发词 | `领英找工作`、`匹配职位`、`找 AI 开发工作`、`海外远程工作` |

Skill 被触发后自动跑完：去重 → 过期检测 → HTML 生成，浏览器打开结果页面。

## 1. 导 Cookie（仅需一次，过期重做）

打开 Chrome → F12 → Application → Cookies → `www.linkedin.com` → 把所有条目复制，存为：

```
C:\Users\Lucas\.agents\skills\linkedin-jobs\cookies.txt
```

格式：每行一个 Cookie，制表符分隔 `name	value	domain	path	expires`

关键 Cookie: `li_at`（认证 token），有效期约 1 年，过期了重导即可。

## 4. 筛选规则

| 评分 | 含义 |
|------|------|
| ≥20 | 高度匹配，优先投 |
| 10-19 | 中等匹配，挑着投 |
| <10 | 部分沾边 |

### 去重策略

1. **Job ID 去重**：同一岗位不同子域名（es/jp/cn.linkedin.com）只保留一条
2. **公司去重**：同一公司只保留最高分岗位
3. **过期过滤**：用 requests 批量检测 "no longer accepting applications"

### 为什么用 requests 检测过期而非 Playwright？

LinkedIn 对自动化浏览器返回的渲染内容与真实浏览器不同。`"no longer accepting applications"` 嵌入在页面源码的 `<script>` JSON 中，Playwright 的 `inner_text()` 无法捕获。直接用 requests + `li_at` Cookie 获取原始 HTML → 100% 检测率。

## 5. 自定义

编辑 `search.py`：

- **换关键词** → 改 `SEARCH_QUERIES` 列表
- **换城市** → 改 `geo_id`（上海=102890883，北京=102890259，深圳=102890612）
- **加技能** → 改 `CORE_SKILLS` 列表
- **改时间范围** → 改 `TIME_FILTER`（r86400=24h, r604800=7d, r2592000=30d）

## 6. 常见问题

**Q: Cookie 过期** → 浏览器打开后跳到登录页。重做第 1 步。

**Q: 搜索结果全过期** → Easy Apply 岗位 1-2 天内大量失效属正常。重新运行搜索即可。

**Q: HTML 打开后看到旧数据** → 浏览器缓存，Ctrl+Shift+R 强制刷新。

**Q: 为什么不用自动投递？** → LinkedIn 对 Apply 按钮有最强反自动化保护（challenge-dialog 验证），Playwright Stealth 无法绕过。手动投递是最安全的方式。

**Q: 只搜不投** → 工具只负责发现+筛选+生成列表，投递由你手动决策。

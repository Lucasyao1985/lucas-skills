# 风控层与持仓盈亏计算（v2.4）

## 1. 风控标记（任一触发 → 强制观望）

| 标记 | 触发条件 | 说明 |
|---|---|---|
| `EXTREME_VOLATILITY` | 1h ATR/价格 > **币种画像阈值**（BTC 0.80% / ETH 0.90% / SOL 1.20% / DOGE 1.50%…，见 scoring-model.md §2） | Wilder ATR；v2.4 起按币校准，防高波动币被 BTC 口径误杀 |
| `DATA_STALE` | ≥2 个 K 线周期超时滞 | 见 data-sources.md §2 |
| `DATA_CONFLICT` | 交叉验证偏差 > 0.50% | 重试后仍冲突 |
| `FUNDING_EXTREME` | \|funding\| > **0.0010**（原始小数 = 0.10%/期） | 挤仓风险；旧版误写 0.10 导致永不触发，已修复 |
| `LIQUIDITY_THIN` | 全100档深度 < **币种画像下限**（BTC/ETH/DOGE $1.0M、SOL $1.5M…），周末/UTC 0-4 点 ×0.7 | 实测校准：BTC≈$1.5M、ETH≈$1.75M、SOL≈$4.4M、DOGE≈$1.7M；小市值币下限更低 |
| `AMBIGUOUS_SCORE` | \|composite\| < 20 | 信息性标记；方向死区 ±35 另行兜底 |
| `LOW_CONFIDENCE` | 数据可信度 < 70% | 备源缺失/冲突累积 |
| `POOR_RR` | 盈亏比 < 1.5 且方向非观望 | 支撑阻力过近时常见 |

评估顺序：数据新鲜 → 交叉验证 → ATR → 资金费率 → 深度 → 合成分 → 置信度 → R/R。

## 2. 入场/止损/目标（仅方向 ≠ 观望时计算）

```
做多: 入场 [P×0.9985, P×1.0010]
      止损 max(近支撑 − 0.3×ATR₁ₕ, P×0.985)
      目标1 = 近阻力; 目标2 = 近阻力 + 1.5×ATR₁ₕ
做空: 镜像对称。
支撑/阻力取自最近 48 根 1h K 线的高低点极值。
盈亏比 = (目标1 − 入场高) / (入场高 − 止损)   [做空为镜像]
```

## 3. 持仓盈亏计算器（用户提供持仓时使用）

**铁律：方向以用户陈述为准。用户说做空就按空单算，绝不反推。**

### 字段映射（中文账户截图/口述）
| 用户说法 | 含义 |
|---|---|
| 方向：卖/做空/卖出 | SHORT |
| 方向：买/做多/买入 | LONG |
| 平均价格 / 持仓成本 | entry_price |
| 成交数量 / 持仓数量 | quantity |
| 成交额 | position_value = entry × qty（≠保证金！） |
| 保证金 | margin |
| 杠杆 | leverage |
| 浮动盈亏 | floating_pnl —— **以此为准验证计算** |

### 公式
```
多单: pnl   = (现价 − 开仓价) × 数量
空单: pnl   = (开仓价 − 现价) × 数量
pnl_pct     = 价差 / 开仓价 × 100
保证金占用% = |pnl| / 保证金 × 100        ← 杠杆只影响此项，不影响 pnl 本身
```

### 输出规则
1. 先声明方向："你是做多/你是做空"。
2. 用户报的浮动盈亏是 ground truth——自算值与其偏差 >10% 时提请确认，不要坚持自己算的对。
3. 分步展示公式，方便用户核对。
4. 止损默认建议：亏损 ≤ 保证金 50% 的位置。
5. 建议平仓前必须先与用户确认。

### 高频错误对照
| 错误 | 为什么错 |
|---|---|
| 给空单按多单算 | 方向反转，信任崩塌 |
| pnl 再乘杠杆 | 杠杆影响保证金占用%，不改变美元盈亏 |
| 把成交额当保证金 | 成交额 = 仓位名义价值 |
| 忽略用户报的浮动盈亏 | 实盘数字优先于模型 |

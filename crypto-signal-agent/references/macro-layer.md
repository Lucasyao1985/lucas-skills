# 宏观层：美联储政策面与事件门控（v2.3 新增）

> 回答"模型考虑美联储政策了吗"：v2.2 之前不考虑（纯量化失明）；
> v2.3 起通过**两条确定性门控**纳入宏观考量。

## 设计哲学

宏观/新闻面无法量化成稳定因子权重（数据源不稳定、市场定价难以校准），
因此遵循 skill 核心原则——**抑制信号而非假装精确**：

1. **已知事件 → 静默窗**：FOMC 议息、CPI、非农等高影响事件的发布时间是
   **事先确定的**，完全可程序化。窗口内不产出方向信号。
2. **未知冲击 → 代理变量**：政策对山寨币的即时传导几乎必经 BTC，
   用 BTC 状态做联动门控，替代不可靠的 DXY 免费数据源。
3. **解读留给分析者**：stdout 契约保持干净；事件上下文写入 notes/debug，
   由运行 skill 的模型在对话中结合新闻自行解读。

## 门控一：MACRO_EVENT_WINDOW（事件静默窗）

- 数据源：ForexFactory 本周公开日历 `nfs.faireconomy.media/ff_calendar_thisweek.json`
  （免费、无需 key；含 FOMC 声明/纪要、CPI、非农、PCE、Powell 讲话等）
- 过滤条件：`country == USD` 且 `impact ∈ {High, Medium}`
- **High 事件**：发布前 120 分钟 ~ 后 60 分钟 → 触发
  `MACRO_EVENT_WINDOW` → **强制观望**
- **Medium 事件**：±3 小时 → 仅写入 notes 提示（初请失业金这类事件噪声大，
  通常已被定价，不封锁信号）
- 日历不可达 → 仅记 notes「宏观日历不可用」，不惩罚置信度（补充层缺失 ≠ 数据冲突）
- 输出附加信息：未来 24h 内的下一个 High 事件及剩余小时数

## 门控二：BTC_REGIME_CONFLICT（BTC 联动）

仅作用于非 BTC 币种（BTC 自身跳过）：

| 条件（以做多山寨为例） | 动作 |
|---|---|
| BTC 24h ≤ −5%（暴跌） | `BTC_REGIME_CONFLICT` → **强制观望** |
| BTC 24h ≤ −2% 或 1h EMA 空头排列 | 置信度 −10 并记 notes |
| BTC 横盘/同向 | 不干预 |

做空方向镜像对称。逻辑依据：山寨币对 BTC 的贝塔通常 >1，
逆着 BTC 的暴跌趋势做多久期只有 1 小时的山寨信号，胜率结构性偏低。

## 已知局限（诚实声明）

- ForexFactory 日历覆盖**本周**；跨周边界处（周日晚）下周事件可能暂缺。
- 静默窗参数（120/60 分钟）为经验值，未按事件类型细分。
- 政策**预期变化**（如点阵图转向、官员鹰派讲话）不在日历里，
  只能由运行 skill 的 LLM 结合实时新闻补充判断——脚本层无法覆盖。
- 地缘政治黑天鹅无任何日历可依。
